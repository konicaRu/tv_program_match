## 1. Цель и рамки

Разработать русскоязычное мобильное веб-приложение (PWA), которое можно добавить ярлыком на главный экран Android. Приложение собирает **российские гонки**, их прямые эфиры и **все обнаруженные повторы** на каналах семейства «Матч», а также **международный биатлон (в том числе Кубок мира и чемпионат мира)** исключительно по фактической программе трансляций/записей Okko. Доступ с телефона по HTTPS без установки APK. Вдохновение по структуре календаря: https://beonedge.racing/. Визуальное направление — близкое спортивной айдентике IBU, без копирования чужих логотипов, графики или защищённого дизайна.

**Важно:** приложение — расписание ПРОСМОТРА, а не календарь гонок. Показывать только подтверждённые трансляции или доступные записи на «Матч» и Okko. Время начала гонки из IBU не использовать для заполнения расписания и не выводить отдельной обязательной строкой. Для каждого события учитывать один или несколько эфиров/повторов. Не выдумывать передачи и ссылки на воспроизведение.

### Что входит в MVP
- Объединённая лента ближайших событий, группировка по дням; вкладки `Все`, `Россия`, `IBU`, `Повторы`.
- Каждая карточка: дата и время трансляции по Москве, турнир, этап/город, дисциплина, мужчины/женщины/смешанная, статус, источник, канал/платформа, прямой эфир/повтор/запись, время **каждого** показа.
- Карточка гонки раскрывается: все эфиры в хронологическом порядке, включая повторы на других каналах, ссылки `Открыть Матч` и `Открыть Okko` только для подтверждённых страниц.
- Быстрые фильтры `Сегодня`, `Завтра`, `7 дней`, `Все`; заметное обозначение `МСК`; отметка `Расписание обновлено ...` и предупреждение об устаревших данных.
- Установка ярлыка PWA на Android, собственная иконка, адаптивная мобильная вёрстка, базовая offline-страница/кеш последнего расписания.
- Автоматическое обновление данных в GitHub Actions + публикация через GitHub Pages.
- Отдельные экраны спортивной статистики по разделу 10, включая результаты российских гонок и отдельные общие зачёты мужчин и женщин.

### Не входит в MVP
- Перетрансляция видео/пиратские потоки, обход подписок Okko.
- Точные push-уведомления, серверная база данных, личные аккаунты, официальный бренд IBU.
- Зачёты отдельных дисциплин и Кубок наций — возможно позже.

**Discovery/spike — обязательный первый этап.** Найти доступные официальные API/JSON/HTML/ICS, исследовать network-запросы браузера, robots.txt, ограничения, пагинацию и дату публикации телепрограммы. Функция ручного внесения подтверждённого эфира из небольшого `overrides.json` допускается до появления надёжного парсера. Проверять реальные условия сервиса/права, не обходить капчи, логин, DRM и защиту.

## 3. Модель данных

Основная сущность — `broadcast` (реальный показ), а `event` служит лишь группировкой повторов. Не требовать даты старта гонки и не обращаться к IBU за расписанием.

```json
{
  "event_id": "world-cup-stage-sprint-men-example",
  "competition": "Кубок мира",
  "discipline": "Спринт",
  "category": "international",
  "broadcasts": [
    {
      "broadcast_id": "okko-example-1",
      "platform": "OKKO",
      "channel": "Okko",
      "type": "live",
      "start_utc": "2026-12-01T12:00:00Z",
      "url": null,
      "verified_at": "2026-11-24T17:00:00Z",
      "source_url": "https://okko.tv/collection/root-sport"
    }
  ]
}
```


**Пример выше — только схема, а не реальные данные эфира.** В actual output запрещены выдуманные записи.

- `event_id`: детерминированный идентификатор события для группировки нескольких показов; независимый `broadcast_id` для каждого эфира.
- `broadcast.type`: `live | delayed | replay | recording | unknown`; `delayed` — отложенный первый показ, `replay` — подтверждённый повтор; `recording` — запись по требованию.
- `start_utc`: ISO UTC, при отображении `Intl.DateTimeFormat('ru-RU', {timeZone:'Europe/Moscow', ...})`; не прибавлять `+3` вручную.
- Указывать `source_url`, `fetched_at`, `verified_at`, `confidence`, `schedule_version`. Время эфира может отличаться от старта гонки.
- `channel` хранить строго согласно названию из программы; нормализовать варианты на уровне адаптера.
- Избегать ложных дублей: нормализовать дисциплину/пол/этап/дату, но **не сливать два отдельных показа**.
- Если трансляция не найдена, **не создавать событие**; если недоступен весь источник, показывать отдельное предупреждение о проблеме обновления данных.

## 4. Архитектура

```text
GitHub Actions (расписание + ручной запуск)
    |-- Python collectors/match_tv.py
    |-- Python collectors/okko.py (при доступности подтверждённой программы)
    |-- adapters/normalize.py + adapters/match_repeats.py
    |-- tests/ (fixtures + проверка дедупликации/часовых поясов)
    `--> public/data/schedule.json + public/data/status.json
                              |
                       GitHub Pages
                              |
                        React + Vite PWA
                              |
                       Ярлык на Android
```

**Выбор стека:** Python (`httpx` + `BeautifulSoup`, при необходимости Playwright только в допустимых пределах) для сбора; React + TypeScript + Vite для интерфейса; `vite-plugin-pwa`/Workbox для манифеста и кеша; CSS variables + адаптивная CSS-вёрстка; `pytest` для коллекторов и `vitest` для функций форматирования. Не нужен постоянно работающий сервер. Рассмотреть статический экспорт вместо React, если хочется предельно простой проект — но выбранный стек удобнее для интерактивной ленты.

**Обновление телепрограммы.** Основную проверку запускать в понедельник по МСК. В воскресенье можно сделать предварительную проверку, если сетка на новую неделю уже опубликована. Брать только опубликованную программу на ближайшие семь календарных дней по МСК. В начале недели учитывать, что эфиры IBU могут начаться со среды, а российские гонки обычно показывают ближе к выходным. Конкретные дни и время брать из сетки.

Если на понедельник уже собраны доступные эфиры и повторы по всему пулу, мониторинг на эту неделю заканчивается. Если часть релевантной сетки ещё не опубликована или запрос завершился ошибкой, при необходимости повторно проверить только недостающие дни и каналы. Для такой проверки оставить ручной `workflow_dispatch`. Публикация Pages отдельная, без коммитов неизменившихся JSON. В `status.json` сохранять время последнего успешного обновления и ошибки источников. При сбое сохранять последние достоверные данные с признаком устаревания.

**Статика / безопасность:** GitHub Pages публичен; не хранить токены, пароли и приватные URL в репозитории или браузере. Никакого скрейпинга авторизованного Okko и никакой публикации его внутренних API-ключей.

- Никакой фальшивой кнопки `Смотреть`; ссылки на страницы официальных сервисов, где контент реально существует.

## 10. Расширение MVP: официальная статистика IBU и российского биатлона

Этот раздел обязателен и уточняет предыдущие этапы. Источник эфиров остаётся прежним: Матч и Okko. IBU используется для спортивных данных и внутренней привязки гонок, но никогда для генерации неподтверждённых трансляций.

### 10.1. Навигация и защита от спойлеров
- Нижнее меню: Эфиры / Зачёт / Результаты / Участники. Главная — только эфиры и повторы, без победителей, очков и результатов.
- Из карточки международного эфира — переход к стартовому протоколу и отдельная кнопка результатов. Не показывать результаты автоматически.
- Все времена в интерфейсе — МСК. Интерфейс на русском, имена спортсменов сохранять в официальном написании IBU.

### 10.2. Общий зачёт Кубка мира
- Две вкладки: мужчины и женщины. Текущий сезон, полный список, место, спортсмен, страна/флаг, очки.
- Сохранять официальные места, включая равенство очков. Не рассчитывать очки самостоятельно.
- Показывать сезон, дату обновления и ссылку на источник. Отдельные зачёты дисциплин и Кубок наций вне MVP.

### 10.3. Стартовые протоколы
- Отдельный экран гонки: стартовый номер, имя, страна, время старта и группа при наличии. Для пасьюта — стартовое отставание при наличии.
- Эстафеты: номер команды, страна, спортсмены в официальном порядке этапов. Поддержать мужские, женские, смешанные и одиночные смешанные эстафеты; в последнем случае не предполагать четыре разных спортсмена, показывать фактический порядок этапов/повторных выходов по протоколу.
- Отображать статус публикации, изменения состава, DNS при наличии. Если протокол отсутствует — явно сообщить об этом.

### 10.4. Результаты гонок
- Отдельная вкладка: выбор гонки, место, имя/команда, страна, время, отставание, промахи, очки при наличии. Для эстафет — командный итог и результаты этапов, если опубликованы.
- Сохранять DNS/DNF/DSQ и предварительный/официальный статус. Не заменять отсутствующие значения нулями.

### 10.5. Источники и архитектура
- Проверить официальный сайт https://www.biathlonworld.com/ и официальный Datacenter https://biathlonresults.com/. Найти разрешённый машиночитаемый источник зачётов, стартовых протоколов и результатов; конкретные API и схемы подтвердить экспериментально, не считать их заранее доступными.
- Отдельный адаптер IBU, независимый от адаптеров Match и Okko.
- JSON: standings.json (season, gender, rank, athlete_id, name, nation, points), startlists.json (ibu_race_id, entries, teams, legs, status), results.json (ibu_race_id, rank, athlete/team, time, behind, misses, points, status). В каждом наборе source_url, fetched_at, published_at при наличии.
- Привязка event_id к ibu_race_id по сезону, турниру, месту, дисциплине, полу и дате исходной гонки, а не дате повтора. Неоднозначные совпадения не связывать автоматически; предусмотреть ручной mapping.
- Обновлять через GitHub Actions независимо от телепрограммы; при сбое сохранять последний валидный набор с отметкой устаревания. Предложение для старта: каждые 30 минут, затем уточнить по ограничениям источника.

### 10.7. Российские результаты и общий зачёт
- В разделах «Зачёт» и «Результаты» дать выбор между российскими соревнованиями и IBU. В российском зачёте показать мужчин и женщин отдельно, с указанием турнира, сезона, места, имени, региона и официальных очков при наличии.
- Для российских гонок показывать результаты из официальных протоколов. На первом этапе подтверждены примеры СБР для Кубка России. Перечень других турниров определить по наличию официальных документов.
- Отдельный адаптер российских результатов. Хранить источник и идентификатор турнира или гонки вместе с записью, сохранять официальные места и статусы, самостоятельно не пересчитывать очки.
- На этапе исследования проверить воспроизводимость получения мужского и женского зачётов и протоколов гонок. На главном экране эфиров российские результаты не показывать.
