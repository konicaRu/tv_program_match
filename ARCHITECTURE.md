# Архитектура BIATHLON TV

Мобильное расписание трансляций биатлона: эфиры и повторы «Матча» и Okko по московскому времени, без результатов в ленте; отдельно — календарь, протоколы, результаты и зачёт IBU, открываемые по запросу. Сервера нет: данные собирает GitHub Actions, приложение — статическая PWA на GitHub Pages.

## Поток данных

```text
matchtv.ru/tvguide/<канал>?date=…  ─┐  (5 каналов × 7 дней)      public/data/sources/<источник>.json
matchtv.ru/biathlon/live?date=…     ─┤
t.me/s/biathlon_match (карточки)    ─┼─ collectors/schedule.py ─► public/data/schedule.json
t.me/s/okkowintersport, okkosport ──┘   (слияние, гонки)          public/data/status.json
bw.biathlonresults.com (+ biathlonworld.com) ─ collectors/ibu.py ─► public/data/ibu/{season,standings,status}.json, races/<RaceId>.json
            │ OCR Tesseract                                             │
                                                                        ▼
        .github/workflows/collect.yml (07:15 и 19:15 МСК)       коммит только при изменениях
                                                                        │ вызывает
                                                                        ▼
        .github/workflows/deploy.yml: тесты, Playwright, сборка ─► GitHub Pages (PWA)
                                                                        │
                                       https://konicaru.github.io/tv_program_match/
```

## Компоненты

| Файл | Что делает |
|---|---|
| `collectors/match_guide.py` | Дневные сетки «Матч ТВ», «Страны», «Арены», «Игры», «Премьера». Берёт строки «Биатлон.» и программу «Биатлон с Дмитрием Губерниевым». Показы после полуночи, пометки «прямая трансляция» и «повтор», повтор по совпадению названия в пределах суток. Неопубликованный день (`--availability-not-available` в календаре) — не ошибка, а `unpublished`. |
| `collectors/match_tv.py` | Раздел matchtv.ru/biathlon/live по дням (`collect_live`): второй официальный источник «Матча», только прямые эфиры «Матч ТВ». Пустой `broadcast__list` — день без биатлона, отсутствие списка — сбой; страница, показавшая другой день, — сбой. Общий тип `Broadcast`. |
| `collectors/match_telegram.py` | Резервный источник «Матча» (`match_telegram`): карточки-расписания в Telegram-канале «Матч! Биатлон и лыжи» @biathlon_match (та же карточка выходит в vk.ru/biathlon_match). Карточка — заголовок с соревнованием («Биатлон. Альфа-Банк Кубок Содружества»), строки дат и «07:45 Спринт. Мужчины», включая «Биатлон с Дмитрием Губерниевым». Подписи у карточек нет, поэтому OCR проходят все картинки постов за неделю до окна (около 40 с). Обработка своя: оставляет светлый серо-белый и золотой текст, синий фон убирает (`light_text`). Нужны слово «биатлон» и соревнование; строка берётся, только если начинается со времени (время с секундами или десятыми — результат или старт, не эфир) и ясны дата, дисциплина и пол. Фото, которое не скачалось или не распозналось, пропускается; сбой источника — только нечитаемая страница канала. Только «Матч ТВ» и только прямые эфиры; `broadcast_id` как у телегида (`match-matchtv-<время>`). |
| `collectors/okko_telegram.py` | Официальные каналы Okko: @okkowintersport (источник `okko_telegram`) и @okkosport (`okko_sport`, перепосты тех же расписаний). Канал листается назад, пока посты не станут на неделю старше окна (не больше 30 страниц); эфиры, которые канал дал раньше, помнятся, пока их день в окне, а новый пост о той же гонке и дне их заменяет. Посты со словами «расписание» и «биатлон», картинки → OCR (только белый текст, увеличение ×3, порог 170, `--psm 4`). Строка берётся, только если ясны дата, время, дисциплина и пол; при нечитаемой дате строки под ней отбрасываются. Новый пост о той же гонке и дне заменяет старый. Ссылка на пост — подтверждение. |
| `collectors/schedule.py` | Каждый источник — `SourceRun`; его удачный результат хранится в `sources/<имя>.json`, при сбое берутся последние сохранённые показы (а если файла ещё нет — показы из прежнего `schedule.json` по адресу источника). Слияние по `broadcast_id` в порядке приоритета: телегид → раздел биатлона → @okkowintersport → @okkosport; резервный источник (`BACKUP_SOURCES`: карточки @biathlon_match) идёт в ленту, только если ни один другой источник не даёт ту же гонку на том же канале в пределах 90 минут (канал сравнивается без учёта регистра: раздел биатлона пишет «МАТЧ ТВ»); у дубля недостающие тип, окончание и ссылка берутся из второго. Показы раньше сегодняшнего дня МСК отбрасываются. Разбор названия на соревнование, дисциплину, пол и категорию; событие = гонка (показы дальше трёх дней — новый этап) или недельный выпуск программы. Атомарная запись JSON, без изменений ничего не пишет. |
| `collectors/ibu.py` | Календарь сезона (`Events`, `Competitions`; только Кубок мира, чемпионат мира, Олимпиада), протоколы и результаты (`Results?RaceId`) для гонок от недели назад до двух недель вперёд, общий зачёт (`CupResults`, `BT<сезон>SWRLCP__SMTS/SWTS`). Названия гонок по-русски («Спринт · Мужчины · 10 км»), состояние гонки по `ResultStatus`. Резерв: `__NEXT_DATA__` страниц `/startlist/<RaceId>` и `/calendar` на biathlonworld.com. Основной адрес biathlonresults.com без `bw.` требует ключ (401) — не используется. Пишет только изменившиеся файлы; не полученный кусок оставляет прежний файл и попадает в `ibu/status.json`. |
| `src/lib/ibu.ts`, `src/IbuViews.tsx` | Разделы «Гонки» (этапы, гонки, стартовый протокол, результаты за кнопкой) и «Зачёт» (за кнопкой, вкладки «Мужчины/Женщины»). Файлы с результатами и зачётом загружаются только при переходе в раздел. Маршруты по хешу: `#/`, `#/races`, `#/race/<RaceId>`, `#/standings`. |
| `collectors/notify.py` | Напоминания в Telegram по `schedule.json` и `ibu/season.json`: во вторник в 09:00 — гонки недели по соревнованиям (гонки IBU сопоставляются с эфирами по времени старта, без эфира — «трансляция пока не объявлена»; российские гонки — по первому показу события), сводка дня в 09:00 МСК (с текущего момента, повторы помечены), «Завтра» в 19:00 и напоминание, когда до первого показа меньше 45 минут. Тихие часы до 09:00, эфиры до 09:00 без напоминаний, повторы без напоминаний, одновременные каналы одним сообщением. Отправленное хранится в `.notify-state/state.json` (кэш Actions), записи старше суток забываются. Состояние сохраняется, даже если Telegram отклонил одно из сообщений: остальные отправляются, доставленные не повторяются, отклонённое не переотправляется, запуск завершается ошибкой. Токен и chat id — секреты `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`; без них ничего не отправляется. Перед отправкой `getChat` проверяет, что чат личный (`type: private`); канал или группа — остановка без отправки. |
| `collectors/alert.py` | Сообщения о сбоях тем же ботом и только в личный чат, простым русским языком: что сломалось, что значит ошибка, что видно в приложении, что делать. `sources` — после сбора сравнивает `status.json` и `ibu/status.json` с копией до сбора: источник, который только что сломался, — одно сообщение, починился — «снова работает»; плюс гонки Кубка мира в ближайшие 48 часов, для которых ни один источник не дал эфира (±30 минут от старта IBU), — один раз, когда гонка входит в это окно. `workflow` — упавшие шаги запуска Actions (по `gh run view --json jobs`) с пояснением для каждого известного шага; шаг «Report source errors» пропускается, его объясняет `sources`. Для напоминаний (раз в 10 минут) — только первый сбой подряд. Без секретов только печатает. |
| `src/lib/schedule.ts` | Типы данных, группировка по московским дням (событие видно в каждый день, когда есть показ), подписи, состояния «Сейчас»/«Завершено» только при известном окончании. |
| `src/App.tsx`, `src/styles.css` | Лента: полоса дней, карточки с временем, пометками и каналами, раскрытие «Время трансляций», предупреждение об устаревании. |
| `vite.config.ts` | База `/tv_program_match/`, манифест и service worker (`vite-plugin-pwa`); данные кешируются «сначала сеть» по литеральному шаблону (функция в `sw.js` не видит переменных конфига). |

## Модель данных

- `schedule.json`: `events[]` (`event_id`, `kind: race|show`, `title`, `competition`, `discipline`, `gender`, `category`, `broadcasts[]`) и `unmatched[]` — показы, которые не удалось уверенно отнести к гонке.
- `broadcast`: `broadcast_id`, `platform` (`MATCH`/`OKKO`), `channel`, `title` (как в источнике), `type` (`live|replay|unknown|…`), `start_utc`, `end_utc`, `url`, `source_url`, `verified_at`.
- `status.json`: `checked_at`, `last_success`, `stale`, `errors{url: текст}`, `unpublished[]`, `sources{имя: {last_success, stale, errors}}`.
- `sources/<имя>.json`: `source`, `fetched_at`, `broadcasts[]` — последний удачный результат источника.
- `ibu/season.json`: этапы (`event_id`, `name`, `country`, `kind`, даты) и гонки (`race_id`, `title`, `discipline`, `gender`, `km`, `start_utc`, `state`, `has_startlist`, `has_results`, `url`). `ibu/races/<RaceId>.json`: строки протокола или результатов (`bib`, `name`, `nat`, `is_team`, `start_time`, `rank`, `total_time`, `behind`, `shootings`, `wc_points`, `irm`). `ibu/standings.json`: `men`/`women` с `race_count`, `total_races`, `rows` (`rank`, `name`, `nat`, `score`).
- Время в данных — UTC, в интерфейсе — Europe/Moscow через `Intl`.

## Проверки

- Python: `python -m unittest discover -s tests` (на реальных сохранённых страницах «Матча» и постах Okko; тест OCR — только где установлен Tesseract).
- Приложение: `npm test` (vitest, в том числе в чужом часовом поясе), `npm run build`, `npm run test:e2e` (Playwright на 360/390/430 px и работа собранного приложения без сети).

`.github/workflows/notify.yml` запускает `collectors.notify` каждые 10 минут с 09:00 до 23:59 МСК; ручной запуск с флагом «тест» шлёт проверочное сообщение.

**Сообщения о сбоях.** `collect.yml` копирует `public/data` до сбора и после него вызывает `collectors.alert sources`; отдельная задача `alert` при упавшей сборке или публикации вызывает `collectors.alert workflow`. Такие же задачи есть в `deploy.yml` (только для его собственных запусков после пуша; из `collect.yml` о нём сообщает `collect.yml`) и в `notify.yml` (`--only-first`). Сторож СБР пишет в Telegram, когда открывает issue. Шаги с сообщениями помечены `continue-on-error`: сбой Telegram не ломает сбор.

**Временное:** `.github/workflows/watch-sbr.yml` каждые три часа сохраняет главную biathlon-results.ru и страницы соревнований из её списка как артефакт `sbr-pages` и один раз создаёт issue, когда соревнования появятся. Удалить после появления сборщика СБР.

Команды запуска описаны в README, правила работы с данными — в [конституции проекта](docs/constitution.md), проверка источников — в [docs/SOURCES.md](docs/SOURCES.md).
