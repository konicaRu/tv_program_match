# Архитектура BIATHLON TV

## Текущее состояние

В репозитории документация, примеры телепрограммы, два парсера и сборщик расписания. `collectors/match_tv.py` читает сохранённый биатлонный раздел. `collectors/match_guide.py` запрашивает дневные сетки пяти каналов, сопоставляет повторы с более ранним прямым эфиром той же гонки и отличает ещё не опубликованные дни от сбоев. `collectors/schedule.py` разбирает название передачи на соревнование, дисциплину и пол, объединяет показы одной гонки в событие и атомарно пишет `schedule.json` и `status.json`. Workflow `.github/workflows/collect.yml` ежедневно решает, нужен ли сбор, и коммитит обновлённые данные в `public/data/`. Приложение React + Vite + TypeScript (`src/`) читает эти JSON, группирует показы по московским дням (`src/lib/schedule.ts`) и работает как PWA через `vite-plugin-pwa`: данные кешируются по принципу «сначала сеть». Сценарии интерфейса проверяются Playwright (`e2e/`). `.github/workflows/deploy.yml` проверяет и собирает приложение и публикует его на GitHub Pages при пуше в `main`. Коммиты бота встроенным токеном не запускают другие workflow, поэтому `collect.yml` после изменения данных сам вызывает `deploy.yml`.

## Планируемая структура

- Адаптеры «Матча» и Okko собирают данные о подтверждённых показах. Гонка объединяет несколько показов, у каждого свой идентификатор.
- Отдельные адаптеры IBU и российских соревнований собирают спортивную статистику.
- GitHub Actions обновляет JSON, GitHub Pages публикует PWA на React и Vite. При сбое источника приложение сохраняет доступ к последним подтверждённым данным и сообщает об их устаревании.
- Телепрограмма собирается по опубликованной сетке на ближайшие семь дней. Основная проверка в понедельник по МСК, повторная нужна только при пробелах в сетке.

Команды запуска и проверки описаны в README. Правила работы с данными описаны в [конституции проекта](docs/constitution.md).
