# BIATHLON TV

Мобильное расписание просмотра биатлона с эфирами, повторами и записями, плюс календарь, стартовые протоколы, результаты и общий зачёт IBU. В интерфейсе время отображается по Москве. Российские и международные результаты и зачёты открываются отдельно от ленты эфиров.

Сейчас готовы сбор телепрограммы пяти каналов «Матча» и расписаний Okko и мобильное приложение с лентой эфиров. Показы группируются по гонкам и обновляются автоматически через GitHub Actions. Приложение публикуется на GitHub Pages: https://konicaru.github.io/tv_program_match/ Для запуска нужен Python 3.11 или новее.

```powershell
python -m pip install -r requirements.txt
python -m collectors.match_tv tests/fixtures/match/2026-11-28.html --source-url "https://matchtv.ru/biathlon/live?date=28-11-2026"
python -m unittest discover -s tests -v
```

Парсер выводит JSON со временем показов в UTC. Тип показа без явной пометки в строке остаётся `unknown`.

Чтобы вручную собрать телесетки пяти каналов на ближайшие семь дней, запустите:

```powershell
python -m collectors.match_guide
```

Для одного дня укажите `--start YYYY-MM-DD --days 1`. Команда выводит показы, ошибки источника и ещё не опубликованные дни в JSON. Если хотя бы одна страница недоступна, код выхода равен 1, а успешно прочитанные показы остаются в выводе.

Чтобы собрать данные для приложения, запустите:

```powershell
python -m collectors.schedule
```

Команда опрашивает пять источников: телепрограмму пяти каналов «Матча», раздел биатлона matchtv.ru/biathlon/live (второй официальный источник прямых эфиров), карточки-расписания в Telegram-канале «Матча» [@biathlon_match](https://t.me/biathlon_match) (резерв: идут в ленту, только если других данных о гонке нет) и расписания Okko в двух Telegram-каналах. Каналы листаются на неделю назад, а эфиры из уже прочитанных постов помнятся, пока их день не прошёл. Последние удачные показы каждого источника хранятся отдельно в `public/data/sources/`, и лента собирается из всех: если один источник недоступен, в ленту идут его последние данные, а остальные обновляются. Одинаковые показы из двух источников склеиваются. Показы одной гонки объединяются в событие, выпуски программы «Биатлон с Дмитрием Губерниевым» — в событие `show` по неделям. Результат — `public/data/schedule.json` и `public/data/status.json`; в статусе по каждому источнику видно время последнего успешного обновления и ошибки, приложение называет отставший источник. Показы с неясным названием попадают в `unmatched`, ещё не опубликованные дни ошибкой не считаются и перечислены в `unpublished`.

Эфиры Okko берутся из расписаний-картинок в официальных Telegram-каналах [Okko Зимний Спорт](https://t.me/okkowintersport) и [Okko Спорт](https://t.me/okkosport) (второй перепостит те же расписания и служит резервом): `collectors/okko_telegram.py` распознаёт их через Tesseract и оставляет только строки с понятными датой, временем, дисциплиной и полом. Для локального запуска нужен Tesseract с русским языком (`tesseract-ocr-rus`); тесты распознавания без него пропускаются.

Сбор запускается автоматически через GitHub Actions ([collect.yml](.github/workflows/collect.yml)) дважды в день, в 07:15 и 19:15 МСК: Okko публикует расписание этапа в середине недели. Если эфиры и состояние источников не изменились, ничего не коммитится и не публикуется. Иначе свежие `public/data/schedule.json` и `public/data/status.json` коммитятся в репозиторий, после чего приложение публикуется заново.

Данные IBU (календарь этапов Кубка мира, чемпионата мира и Олимпиады, стартовые протоколы и результаты гонок за неделю назад и две недели вперёд, общий зачёт мужчин и женщин) собирает `collectors/ibu.py` в `public/data/ibu/` — из публичного адреса дата-центра IBU, которым пользуется сайт biathlonworld.com, а при сбое из страниц самого сайта.

Приложение написано на React, Vite и TypeScript. Для запуска нужен Node.js 22 или новее:

```powershell
npm install
npm run dev
```

Откройте http://localhost:5173/tv_program_match/. Нижнее меню: «Эфиры» — лента по дням, карточка гонки или программы со всеми показами и повторами, предупреждение об устаревших данных; «Гонки» — календарь IBU и стартовые протоколы, результаты открываются только кнопкой «Показать результаты»; «Зачёт» — общий зачёт Кубка мира, открывается кнопкой «Показать зачёт». Из карточки эфира, который начинается со стартом гонки, есть ссылка на её протокол. Время всегда московское. Проверки: `npm test` (функции ленты), `npm run build`, затем `npm run test:e2e` (сценарии Playwright на ширине 360, 390 и 430 px и работа собранного приложения без сети; перед первым запуском `npx playwright install chromium`).

Публикацию выполняет [deploy.yml](.github/workflows/deploy.yml): при каждом пуше в `main` и после обновления данных он прогоняет тесты и сценарии Playwright, собирает приложение и выкладывает его на GitHub Pages.

## Напоминания в Telegram

Ваш бот присылает: во вторник в 09:00 МСК — гонки недели по соревнованиям и где их смотреть (гонки Кубка мира берутся из календаря IBU, пока Okko не опубликовал эфиры, — с пометкой «трансляция пока не объявлена»); каждый день в 09:00 — эфиры на сегодня; в 19:00 — эфиры на завтра; примерно за 40 минут — напоминание о каждом первом показе. Бот пишет только в личный чат с вами: если `TELEGRAM_CHAT_ID` указывает на канал или группу, он ничего не отправляет и пишет об этом в журнал запуска. Раньше 09:00 сообщений нет, о гонках до 9 утра бот не напоминает, о повторах — только в сводках. Результатов в сообщениях нет. Если что-то сломалось, тот же бот пишет, что случилось и что делать, простым языком: источник данных перестал отвечать (и потом — что снова работает), для гонки Кубка мира в ближайшие двое суток не нашлось трансляции, упали тесты, сборка, публикация сайта или сами напоминания (о напоминаниях — один раз, пока сбой не пройдёт); когда на biathlon-results.ru появятся соревнования СБР — тоже сообщение. Работает [notify.yml](.github/workflows/notify.yml) каждые 10 минут с 09:00 до 23:59 МСК; GitHub может запускать его с опозданием на несколько минут.

Подключение:

1. Токен бота — у [@BotFather](https://t.me/BotFather): `/mybots` → ваш бот → **API Token** (вида `123456789:AA…`).
2. Напишите своему боту `/start` (иначе он не сможет вам писать) и узнайте свой личный ID — например, у [@userinfobot](https://t.me/userinfobot). Это положительное число; номер канала или группы (начинается с `-100`) не подходит.
3. На GitHub: репозиторий → **Settings → Secrets and variables → Actions → New repository secret**. Добавьте `TELEGRAM_BOT_TOKEN` (токен) и `TELEGRAM_CHAT_ID` (chat id). Ни в какие файлы репозитория их не вписывать: репозиторий публичный.
4. Проверка: **Actions → Telegram reminders → Run workflow** (галочка «Только проверочное сообщение» включена) — бот пришлёт «Бот BIATHLON TV подключён».
